# Практическая работа №6 — PHP: файлы, JSON, сессии, подготовка к MVC

Дисциплина «Технологии разработки программного обеспечения». Репозиторий: `trpo-pr06-student`.

Небольшое PHP-приложение «Список учебных заметок»: заметки хранятся в JSON-файле, имя текущего пользователя — в `session`, обработка запроса отделена от HTML-шаблонов.

## Требования

- PHP 8.1+ (проверено на 8.4), расширение `mbstring` не нужно.

## Запуск

```bash
git clone https://github.com/i-GeKa-i/trpo-pr06-student.git
cd trpo-pr06-student
php -S 127.0.0.1:8000 -t public
```

Откройте http://127.0.0.1:8000/index.php. Каталог `data/` должен быть доступен PHP на запись.

## Структура

| Путь | Назначение |
|---|---|
| `public/index.php` | единая точка входа: маршрут по `?page=`, обработка POST, redirect |
| `public/style.css` | стили |
| `src/storage.php` | `loadJson()` / `saveJson()` — вся работа с JSON в одном месте |
| `src/notes.php` | загрузка и добавление заметок (валидация, уникальный `id`) |
| `src/session.php` | имя пользователя в `$_SESSION`, проверка по `users.json` |
| `src/scenarios.php` | выполнение сценариев из `session_scenarios.json` |
| `src/view.php` | `render()` и `e()` (экранирование) |
| `templates/` | только HTML: `layout`, `notes`, `scenarios`, `404`, `error`, `userbar` |
| `data/` | рабочие JSON-файлы (в них пишет приложение) |
| `dataset/` | исходный dataset, не изменяется |
| `docs/` | чек-лист проверки |

## Использование dataset

- `notes.json` — список заметок на странице «Заметки»; сюда добавляются новые.
- `users.json` — список пользователей в шапке; выбранное имя сохраняется в session.
- `session_scenarios.json` — таблица на странице «Сценарии session»: кнопка выполняет сценарий над session и сравнивает фактическое состояние с `expected`.

## Файловое хранилище, session, шаблоны

**Файловое хранилище.** `loadJson()` читает файл через `file_get_contents` + `json_decode(..., JSON_THROW_ON_ERROR)`, `saveJson()` пишет через `file_put_contents` с `LOCK_EX`. Если файла нет или JSON повреждён, выбрасывается `StorageException`, и пользователь видит страницу с понятным сообщением (HTTP 500), а не fatal error. `id` новой заметки = максимальный `id` + 1.

Ограничения: нет транзакций (блокируется только запись, а не цикл «прочитал → изменил → записал», поэтому два одновременных запроса могут затереть друг друга); файл читается целиком; нет поиска и индексов; нужны права на запись в `data/`. Для большого объёма нужна БД.

**Session.** `session_start()` вызывается в начале `index.php` до любого вывода. В session лежит только состояние пользователя (`display_name`, одноразовые сообщения `flash`, результаты сценариев); сведения о пользователях берутся из `users.json`. Session привязана к cookie браузера, поэтому в приватном окне имя — «Гость» (там своя, пустая session). Данные session хранятся на сервере и пропадают после истечения или очистки.

**Разделение обработчика и шаблона.** `public/index.php` и `src/` готовят данные, `render($template, $data)` подключает файл из `templates/`. Шаблоны не читают JSON и не меняют session, а выводят данные через `e()`. После успешного POST выполняется redirect (Post/Redirect/Get), поэтому обновление страницы не повторяет действие. Неизвестный `page` даёт страницу 404.

Ограничения: маршрутизация — `if/elseif` в одном файле, вместо классов — глобальные функции. При росте проекта это заменяется контроллерами и репозиториями (MVC).

## Сценарий проверки

1. «Заметки» — видны 2 заметки из `notes.json`.
2. Отправьте заметку из пробелов — сообщение об ошибке, файл не изменился. Добавьте нормальную — она появится в списке и в `data/notes.json`; обновите страницу (F5) — дубликата нет.
3. В шапке выберите «Student B» → «Войти» — имя в шапке. «Очистить» — снова «Гость».
4. «Сценарии session»: выполните все три — колонка «Сейчас» совпадает с «Ожидается». Откройте сайт в приватном окне — «Гость».
5. `index.php?page=zzz` — страница 404.
6. Испортите или удалите `data/notes.json` — страница «Не удалось загрузить данные». Верните файл (образец в `dataset/`).
